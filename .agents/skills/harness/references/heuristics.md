# Heuristics

Distilled from this repository's traces. Each entry is a verified fact plus the
action it implies.

- **`do-harness eval` reports `structure=unknown` when `quick_validate.py` is missing from its sandbox and `evals=none` for a skill without fixtures — both are gaps, not passes.** Keep the gate vendored at `.agents/skills/skill-creator/scripts/quick_validate.py` and give every skill an `evals/evals.json` (from the harness/skill-creator work).
- **`do-harness verify --changed` selects from git state; a change that touches no matching path skips fmt/check/clippy/test/loc.** Preview with `do-harness explain --set verification --changed` and run the full `--set verification` before claiming completion (from the client-integration exercise).
- **MCP protocol truth lives in `crates/mcp-server/src/handle.rs`: `MODERN_VERSION = 2026-07-28` (`server/discover`), `LEGACY_VERSION = 2025-11-25` (`initialize`), fixed tool order with `ttlMs: 300000` and `cacheScope: private`, and `session` defaults to `"default"` when a client omits it.** Change code and its tests together; clients cache `tools/list` (from the MCP server implementation).
- **A process transformer only stays reversible when the configured vault resolves the placeholders it emits; memory/JSON vaults resolve only tokens they issued themselves.** Pair `--transformer process` with `--vault process` over the same store, otherwise restore fails with "which the configured vault cannot resolve" (`docs/process-plugin.md`).
- **`--vault-file` combined with `--vault memory` or `--vault process` is rejected at startup, and `--vault json` requires `--vault-file`.** Read the CLI validation before blaming a probe (`crates/do-context-shield-cli/src/main.rs`).
- **Process plugins fail closed on a malformed response, invalid span, undecided entity, leftover value, unresolvable placeholder, or non-zero exit; stderr is discarded and error messages never echo input values.** Grading a plugin means asserting failure, not success (`crates/plugin-process/tests`).
- **Feature-gated crates are not in the default suite: `cargo check -p do-context-shield-detector-gliner2 --features gliner2` is a manual step, and without a local `--model-dir` the detector fails closed with guidance instead of passing text through.** Do not "fix" a missing model by falling back to passthrough (gliner2 work).
- **`.githooks` plus `core.hooksPath` is the hook source of truth; `do-harness hook install` writes `.git/hooks`, which git ignores when a hooksPath is set.** The two do not combine (upstream conflict detection: d-o-hub/do-harness#108) — pick one (`CONTRIBUTING.md`).
- **Probes, spikes, and client-integration scripts live under `target/` (gitignored).** They are throwaway; never commit them and never let spike code leak into a crate (client-integration exercise).
- **Evidence in `.do-harness/` is local state and fingerprinted against workspace/config state.** `do-harness status --set verification` reports green/red/stale/missing from it; a config edit makes previous green stale.
- **Skills are validated, not prose: only `exists:` / `absent:` / `contains:` / `not-contains:` / `db:` / `cli:` / `walk:` assertions are graded.** Bare strings in `evals.json` count for nothing, and a `gotchas` case needs a negative assertion (`do-harness eval --strict-fixtures`).
- **`scripts/check-loc.sh` warns at 450 lines and fails above 500; `scripts/validate-structure.py` re-checks the ceiling plus required files and the unwrap/expect ban across the tree.** Split before the ceiling: extract a module or a themed `<module>_tests.rs`.
- **`task done` refuses until every sensor-gated subtask has a task-scoped beat: advance to the gated subtask, record its named sensor with `do-harness verify --record --only <sensor> --task <id>`, advance, repeat, then `task done`; `--record` without `--task` only warns and is not task-scoped; re-run `do-harness seed` after editing `plans/invariants.json`.** Closing a method-gated task, or diagnosing a `task done`/`advance` refusal (from the semantic-boundary slice).
- **After editing a structured catalog such as `plans/invariants.json`, validate the parse immediately: keep the structural trailing comma, re-read the edited region instead of trusting a folded `:raw` rendering for line structure, and run `python3 -c "import json; json.load(...)"` before `do-harness seed`.** Syntax-sensitive edits to JSON/TOML/YAML catalogs (from the semantic-boundary slice).
- **Check a binary's existing error-rendering convention before pinning expected message text: a Rust `main` returning `Result` prints the Debug form, so report the exact observed output instead of changing global formatting mid-plan.** Verifying CLI error output, or when a plan inlines an expected error string (from the semantic-boundary slice).
- **Adding or removing a pipeline stage or capability requires a prose sweep in the same change — README, `AGENTS.md`, `CONTRIBUTING.md`, the `.agents/SKILLS.md` index, `plans/invariants.json`, and `docs/` — because no sensor covers stale enumerations.** Capability additions/removals that leave the capability set stale (truth decay) (from the semantic-boundary slice).
- **`do-harness distill` inserts its reference-template `## Guides` block into `SKILL.md` even when the curated heading exists: inspect the `SKILL.md` diff after each distill run and delete the duplicate block before validating.** Running `distill` against a skill that already links `references/heuristics.md` (from the semantic-boundary slice).
- **A job gated with `if: github.event_name != 'pull_request'` reports its action warnings and config deprecations only after the merge to `main`, one layer per merge — an action bump landed without exercising the job surfaces the next warning set on the next push.** Exercise such jobs pre-merge: use the checkout the action pins, dry-run its bundle (`node dist/actions/drafter/run.js` with `INPUT_CONFIG-NAME=file:.github/release-drafter.yml`, `INPUT_DRY-RUN=true`, the `GITHUB_*` context, and a token), and compare the emitted `::warning::` lines against the previous config as a control (from the Node 24 action sweep).
- **It is the pinned action's own code that must be inspected, not its release notes: `release-drafter@v7` declared `runs.using: node24` and its bundled webhook-name warning code was simply absent, which release notes only implied.** For any action bump, resolve the tag and read the checkout's `action.yml` and the emitting code before claiming a warning class is gone (from the Node 24 action sweep).
- **`config-name: file:…` paths resolve against the repo's `.github/` folder, and a path already starting with `.github/` is not prefixed again, so a control copy placed outside that folder is looked up inside it and fails with "Config file not found".** Put throwaway configs inside `.github/` (deleting them afterwards) or use `file:.github/<name>.yml` when validating a config change locally (from the Node 24 action sweep).
- **A job gated to `main` hides its warnings until after the merge; give it a `dry-run: true` twin that runs the same action and config on pull requests, so a version bump or config edit shows up in the PR check.** The twin must run under read-only permissions — a write-scoped action on a PR branch is a privilege escalation — see `.github/workflows/release-drafter.yml` (from the Node 24 action sweep).
- **A sensor's exit status is the signal: piping `do-harness verify` into `tail`/`head` reports the last command's status, so a failing sensor (e.g. a red `skills` gate) gets committed and pushed unnoticed.** Run the gate bare, or read `${PIPESTATUS[0]}`; never let a display filter sit between a failing gate and a commit (from the Node 24 action sweep).
- **The `skills` gate resolves every backticked `scripts/`, `docs/`, and `.github/` path in skill text against the repository and fails on any that does not exist, so example paths must not parse as one of those tokens.** Verify with `bash scripts/check-skills.sh` after editing skill references; an illustrative path under the ignored build directory is such a token and breaks the gate (from the Node 24 action sweep).
- **Split a file near the 450 LOC ceiling mechanically: extract by exact line range, then prove content preservation by diffing the moved region against `git show HEAD:<path>` with visibility/indentation transforms reversed; extracted items consumed from a sibling module need `pub(crate)`, and the import rewire must be explicit because the workspace pedantic lints reject wildcard imports under `-D warnings`.** Splitting or extracting a module from a file approaching the ceiling (`scripts/check-loc.sh` warns at 450 and fails above 500) (from the LOC-decomposition slice).
- **Direct commits on `main` are refused by `.githooks/pre-commit`; start a `<type>/<description>` branch before committing — `main` lands work through pull requests only, and the squash-merge subject is the PR title.** Committing or landing any change in this repository (from the LOC-decomposition slice).
