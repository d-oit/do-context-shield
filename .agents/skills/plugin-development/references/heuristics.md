# Heuristics
- **Overlap resolution is one shared rule, not a per-detector habit: call `plugin-api::resolve_overlaps` (longest-span-wins; equal lengths keep the reported order), never a hand-rolled leftmost-first pass. Four copies of that sort-and-retain loop existed (privacy-core validation, detector-regex, detector-gliner2, plugin-process) and all four kept the leftmost span, so a later span covering more text — a credential starting inside a shorter entity — was dropped and its uncovered tail stayed raw in sanitized output while the doc claimed longest-span-wins.**: When a detector, a merge step, or the central span validation has to drop overlapping candidates. (from trace 8)
- **In detector-regex SPECS, equal-span overlap ties resolve by list order: place more specific kinds before looser shapes that also match the same text (ssn, credit_card, and us_bank_routing before phone).**: When adding or reordering entity patterns in crates/detector-regex/src/patterns.rs (from trace 1)
- **Validate a candidate detector regex against real-shaped positive and negative fixtures before wiring it in: alternation branches sharing a prefix can truncate a longer form, and a global \b wrapper breaks branches that start or end with ':'.**: When adding or changing alternation-heavy detector patterns such as IPv6 (from trace 1)
- **Assert every alternation branch against its real-world form; a branch that cannot match it is dead weight (OpenPGP armor is `BEGIN PGP PRIVATE KEY BLOCK`, a space-separated `Bearer <token>` carries no `:` or `=`).**: When adding layered credential patterns to detector-regex (from the 2026-09-19 private-key/`Bearer`/`ENCRYPTED` hardening)
- **Local-model sidecars live in `examples/` behind the process protocol, carry an offline `--stub` agent so black-box CLI tests run in CI without the model, and keep the real-model path as a documented manual check.**: When adding a sidecar or example plugin that wraps a local model behind the process protocol. (from trace 4)
- **A third-party engine whose runtime handle is not `Send` (ort sessions) cannot be cached behind a mutex in a `Send + Sync` plugin: own it on a dedicated worker thread, send requests over a channel, load lazily on first use, cache for the plugin lifetime, and shut the worker down on Drop; route exports by on-disk layout in feature-independent code with an explicit fail-closed error for every unsupported or incomplete layout.**: When wrapping a local inference engine behind the plugin traits and its sessions or handles are not Send. (from trace 5)
- **A documented adapter selection surface (a `--*-command` pair, a context flag, a config key) needs its own black-box test through the compiled binary: the protocol-level tests prove the plugin, not the selection. Drive the flag with a distinguishing child (a different span, plan, output, or token) plus a control run without the flag, and assert the fail-closed errors (missing command, timeout, leftover value).**: When adding or changing a CLI flag, MCP argument, or config key that selects a plugin or the processing context. (from the 2026-09-28 adapter-surface coverage slice)
- **The regex crate supports no lookaround: a `\b` right anchor cannot bind after a trailing `-` (a trailing hyphen is a non-word character, so the boundary never holds and end-of-input is not a word edge). For unbounded patterns `[alphabet-with-hyphen]{N,}\b` therefore misses every `-`-final value — but do not add a recovery alternative: with `-` inside the alphabet, `[alphabet]{N-1}-` already matches everything the greedy first alternative covers (and `[alnum]{N-1}-` is a dead subset of it). For exact-width patterns `[alphabet]{N-1}<word-final>\b`, include every allowed word character in the final class, including `_`, alongside a separate `[alphabet]{N-1}-` branch that needs no right anchor: the google_api_key pattern missed underscore-final exact-width values because its final class was `[0-9A-Za-z]` only**: Adding or editing detector-regex SPECS patterns whose character class contains a hyphen or underscore and whose right anchor is \b (from trace 10; underscore variant from trace 12)
- **Quality-corpus values must carry the same prefix as the matching generator in value_for (sk-/xoxb-/AIza/glpat-/pypi-…): a bare alphabet tail matches no pattern and the benchmark only reports 'kind missed generated samples'. Tail length equals the pattern's floor — counting every tail character, including a `-` or `_` final character; and a debug print over all cases of a kind lists every sample, not just the missed one**: Extending crates/detector-regex/tests/quality/corpus.rs generated or separator-tail cases for a token kind (from trace 11; floor wording from trace 12)
- **Tokens with dot-separated segments (such as GitLab routable PATs `glpat-<payload>.<routing>`) must require at least two characters after any dot (`(?:\.[0-9a-zA-Z]{2,})*`) rather than admitting bare `.` in the token alphabet: admitting `.` directly in the alphabet swallows trailing sentence periods in prose (e.g. `Token is glpat-...`), while requiring `(?:\.[0-9a-zA-Z]{2,})*` matches the routable segments completely and stops before prose periods**: Adding or editing detector-regex SPECS patterns whose tokens admit dot-separated metadata or routing suffixes.
